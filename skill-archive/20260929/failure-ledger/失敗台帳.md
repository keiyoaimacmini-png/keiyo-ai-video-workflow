# 共通 失敗台帳

## 目的

この台帳は、司令塔が案件の完了を受け入れるときの条件として使う。各工程の文書に同じ失敗を警告として重ねて書かず、起きた失敗と再発を止める条件をここに1件ずつ登録する。
司令塔は、完了する工程を対象とする項目だけ確認する。

## 登録形式

各 entry は次の項目で記録する。

- ID
- 対象工程（値：PREPARE/SCRIPT/NARRATION/ASSEMBLY/ROUGH_EDIT/DELIVERY。1つ以上）
- 起きた失敗
- 原因
- 再発を止める仕組み＝受理条件
- 根拠
- 司令塔が確認する証拠
- 登録日
- 出典

初期3件の出典案件：AN-S152 job `pv-AN-S152-20260926T114914Z`

## F-001

- ID：F-001
- 対象工程：NARRATION、ROUGH_EDIT
- 根拠：Gate AはNARRATIONとROUGH_EDITで音声の配置前検証を要求し、Gate CはROUGH_EDITで音声配置後に動画配置へ進む順序を要求するため。
- 起きた失敗：壊れたTTS音声を検出する前に、動画を配置した（Gate A/C）。
- 原因：音声を取り込む前にGate Aの実デコード検証を完了しておらず、音声の再生成・配置と動画配置を別々に進めた。
- 再発を止める仕組み＝受理条件：ChatCutの音声取り込みまたは `place_audio` の前に、全音声へ `validate_tts_audio.py --manifest` を実行する。各ファイルは、通常ファイルでサイズが正、音声ストリームあり、コンテナの尺が正、ffmpegのサンプルデコードがエラーなし、の全条件を満たすこと。失敗した音声は配置経路から外し、該当カットだけ再生成してGate Aを再実行する。全音声が通るまでは動画配置を受け入れない。
- 司令塔が確認する証拠：Gate Aのマニフェスト検証結果、失敗時の `invalid-clips.json` と隔離先、再生成後の再検証結果、音声取り込み・配置が動画配置より先であることが分かる実行記録。

## F-002

- ID：F-002
- 対象工程：ASSEMBLY
- 根拠：Gate BはASSEMBLYの `edit_plan.py` 時点で動画配置前に弱い `visual_match` を止めるため。
- 起きた失敗：`visual_match: false`、スコア0のカットを配置した（Gate B）。
- 原因：ASSEMBLYの計画時に弱い映像一致を止めず、ChatCutへ動画を置く前に別候補またはオペレーター確認へ切り替えなかった。
- 再発を止める仕組み＝受理条件：ChatCutへ動画を置く前に、すべてのナレーション対象カットで `visual_match` が true、かつ `visual_match_score >= 1` であることを確認する。条件未達なら、尺を満たす別候補を採用して `assembly-plan.json` と `edit-plan.json` を書き直すか、`HOLD_WEAK_VISUAL_MATCH` で止め、カット番号・スコア・現在の素材の入出力・候補を同じターンに提示する。明示的なオペレーター受理が記録されるまで配置を受け入れない。
- 司令塔が確認する証拠：配置前の `assembly-plan.json` と `edit-plan.json`、各カットの一致値とスコア、弱い場合の差し替え後の計画または `operator-visual-match.json`、ChatCut動画配置がGate Bの解消後であること。

## F-003

- ID：F-003
- 対象工程：ROUGH_EDIT
- 根拠：Gate CはROUGH_EDITで音声を配置・速度設定してから動画・字幕を配置する順序を定めるため。
- 起きた失敗：音声と動画を独立したトラックとして別々に進めた（Gate C）。
- 原因：音声の検証・取り込み・配置を終えてロックする前に、動画の取り込み・配置・字幕配置を開始した。
- 再発を止める仕組み＝受理条件：処理順を固定する。①全音声でGate A、②有効な音声だけを取り込む（1セッション最大4ファイル）、③音声を配置して再生速度を設定する、④その後に限り動画・字幕を取り込み、配置し、最終確認する。音声が無効または再生成中なら、動画配置を受け入れない。`edit-plan.json` の `chatcut_steps` もこの順序を保つ。
- 司令塔が確認する証拠：Gate Aの全件通過、音声取り込みの単位、`place_audio` 完了と再生速度設定の記録、動画・字幕処理の開始時刻、`edit-plan.json` の `chatcut_steps`、最終タイムラインの音声と動画の対応。
