# Phase 1 最小実装計画

**設計段階・コード未変更。** ここでは実装順、確認方法、必要なコード側の変更点だけを示す。コード、既存スキル、元ファイルは今回作らない。

## 1. Phase 1の範囲

Phase 1で完成させるのは、Telop JSONの形と、定義済みデザインをプレビュー・透明素材へ描く最小のRendererである。ChatCutへの新しい連携、映像を見た位置決め、バッチ生成、MCP化はPhase 2以降に回す。

Phase 1の動作確認は、現行の台本・音声・rough-editを壊さないよう、まず固定したサンプルJSONで行う。Gemini台本テンプレート末尾のメタデータ追記は、この計画の実施だけでは有効にしない。

## 2. 11項目の実装順

## 3. Phase 1で作らないもの

- ChatCutへ透明素材を自動投入する連携
- 映像解析による人物・商品・顔・手元・TikTok UIの回避
- Gemini台本テンプレートへの追記の有効化
- 自由なフォント、色、装飾の生成
- バッチ生成、修正ループ、MCPの公開インターフェース
- 視認性、はみ出し、コントラスト、絵文字量の最終的な自動評価

これらは要件書のPhase 2・3、または確認事項として扱う。Phase 1の透明出力ができても、現行のChatCut字幕手順を自動で置き換えたことにはしない。

## 4. 衝突3を有効化するときに必要なコード側変更

以下はGemini台本テンプレートの追記案を実際に有効化するための別作業である。Phase 1のRenderer確認とは分け、すべて完了するまで追記をGeminiへ送らない。

1. **プロンプト組み立てを末尾追記方式にする。** 現行の固定本文、4つの穴埋め記号、出力形式を文字単位で保持し、メタデータ6項目と禁止事項6点は末尾にだけ追加する。既存本文を再生成して置き換える実装にはしない。
2. **出力解析を二層に分ける。** 台本本文・シチュエーション・根拠IDと、役割・意図・感情・重要度・強調候補・映像ヒントを別フィールドへ保存する。メタデータの行がナレーション本文へ混ざらないようにする。
3. **列挙値と個数を検査する。** 役割と感情は定義済み値から1つ、重要度は定義済み値から1つ、強調候補は最大2個、映像ヒントは文字列として扱う。強調候補は実際のセリフ本文の部分文字列であることを確認する。
4. **既存の根拠検査を本文だけに適用する。** `script_stage.py`相当の台本検査と`script_grounding.py`相当の根拠確認が、メタデータの説明文を商品事実やセリフとして数えないようにする。既存の根拠確認の目的や合格条件は変えない。
5. **表示用と実行用を分ける。** `operator_variants`の表示では必要に応じてメタデータを隠し、承認後の固定セリフは本文だけを保存する。NARRATIONと現行の字幕処理には、従来どおり本文だけを渡し、メタデータはTelop Generation AIへ別経路で渡す。
6. **旧形式との互換性を確認する。** 追記なしの現行Gemini出力が従来どおり検査・表示できること、追記ありの新形式は全項目がそろった場合だけ有効になることをテストする。途中だけ追記された出力は、静かに採用せず保留または修正対象にする。
7. **有効化の証拠を残す。** 使用したプロンプト、解析結果、本文とメタデータの分離結果、強調候補の実在確認を、司令塔が確認できる形で保存する。現在の失敗台帳や司令塔の受理条件は今回変更しない。

## 5. 実装完了の判定案

Phase 1は、次の証拠がそろった時点で「Rendererの設計検証ができた」とする。商品動画の粗編集が新方式へ移行した、という意味にはしない。

- `02`の3段階のJSONを読み分けた検査結果
- 初期5種を含む代表プレビュー
- 日本語、縁取り、部分色、絵文字、モーションの確認結果
- 9:16の出力確認
- 透明背景出力のアルファ確認
- 同じ入力・同じフレームで同じ出力になることの確認
- ChatCutの現行字幕手順を変更していないことの確認
