# 静止テロップ運用設計書

## 位置づけ

これは、動きなしの静止の透明PNGテロップを、NARRATION → ASSEMBLY → ROUGH_EDIT の流れへ組み込むための運用案である。設計段階であり、現行スキル、コード、リポジトリ、Obsidian、失敗台帳は変更しない。

Phase 1の間は、現行のChatCut字幕手順と固定位置を有効なものとして扱う。新方式への切り替えは、本文の「有効化条件」を満たし、別途承認された後に行う。

### 確定している範囲

- 出力は、カットごとに1枚の静止透明PNG。サイズは1080×1920、RGBAに統一する。
- 配置位置はPhase 1の固定位置、left=108 / top=316 / width=864 / height=287 とする。
- ProRes 4444、VP9アルファ、PNG連番は採用しない。
- ChatCutでは静止PNGが背景の上で透けることを確認済み。PNG連番は独立した静止画として取り込まれ、アルファ動画2形式は現行確認で配置に使えなかった。
- 静止PNGクリップには手動エフェクト・速度を付けられず、確認したトランジションはクリップ間の切り替えである。クレジット消費の原因が不明なため、ChatCutのAIプロンプト機能は使わない前提とする。
- Rendererの方式はHTML/CSS方式とSVG方式の比較後も採用保留である。

出典：`telop-renderer/memory/DECISIONS.md`、`memory/FAILED.md`、`compare_report.md`、`styles.json`。

## 1. 全体フロー図（テキスト）

```text
台本（Gemini）
  → テロップJSON生成（Telop Generation AI、経路は未決）
  → 検証器
  → Renderer（HTML方式/SVG方式は採用保留）
  → カットごとの透明PNG
  → ChatCut取り込み
  → edit-plan の開始/終了時刻に配置
  → final_verify
```

台本の承認済み本文をテロップ本文の正本とし、Telop Generation AIは見た目を選ぶ。検証器を通らないJSONはRendererへ渡さない。Rendererは本文を言い換えず、固定キャンバス上の透明PNGを出力する。Phase 1では固定位置をPNG側の基準にし、表示時間は`edit-plan`の開始・終了時刻を使う。

## 2. 現行手順との差分

### 現行ROUGH_EDITの字幕手順

現行の`04_工程_rough-edit.md`では、Gate Cの音声先行処理の後に、次の手順を実行する。

> 7. `caption_preset` — apply saved preset `product-video-center` once, then set the shared caption layout to left=108, top=316, width=864, height=287 on the 1080×1920 canvas.
>
> 8. `place_captions` — exact frozen line; use `caption_visual_wrap` for display newlines only.

その後の9番目は`final_verify`である。現行文書には「Telop JSON を実行対象に加える設計は設計段階。有効化まで現行の手順に従う」と明記されている。

### 差分案

新方式を有効化した場合だけ、7番と8番を次のPNG処理へ置き換える。1〜6番の音声検証、音声取り込み、音声配置、速度設定、動画取り込み、動画配置は変えない。

7. `import_telop_png_batch`（名称案）：カットごとの静止透明PNGを、音声・動画の処理後にChatCutへ取り込む。
8. `place_telop_pngs`（名称案）：各PNGを対応するカットへ置き、`edit-plan`の開始・終了時刻に合わせる。本文入力やChatCutの字幕プリセットは使わない。
9. `final_verify`：PNGの透過、カット対応、表示時間、音声・動画との同期をまとめて確認する。

これは現行ファイルへ追加する手順名ではなく、切り替え後の実行案である。切り替え前は、現行の`caption_preset`と`place_captions`を使い続ける。

### 有効化条件（案）

次の証拠がすべてそろい、未決事項を承認した時点で初めて新方式を有効にする。

1. Geminiの本文とメタデータを分離して出力・解析でき、旧形式も誤って採用されない。
2. Telop JSONが検証器を通り、本文、強調、フォント、色、RGBA出力の確認記録がある。
3. HTML/CSS方式またはSVG方式の採用を決め、同じ入力から同じPNGを再生成できる。
4. カット数とPNG枚数、カットIDとファイル名、`edit-plan`の開始・終了時刻と配置結果を突き合わせられる。
5. 音声のGate A〜Cが先に完了し、その後にPNGを取り込む一連のChatCutテストが通る。
6. 本番のPNG取り込み経路、切り戻し、`final_verify`の確認項目を実際のケースで確認する。
7. この文書の案をもとにした失敗台帳・司令塔、スキル文書（`02_共通_配置ゲート.md`、`04_工程_rough-edit.md`）、`references/placement-gates.md`、スクリプト（`timing.py`、`edit_plan.py`）、日付フォルダ更新が、別作業として承認・実施されている。

### ロールバック

新方式を受理できない場合は、次の順で現行経路へ戻す。

1. `edit-plan`のPNG項目を実行対象から外し、新方式の配置を完了扱いにしない。
2. PNGをまだ配置していなければ、現行の7番`caption_preset`と8番`place_captions`を実行する。
3. PNGを取り込み済みだが未受理なら、新方式で追加したPNGクリップだけを取り除き、現行の字幕手順を実行する。取り除けない場合は、完了とせず保留する。
4. 既存の音声・動画・固定位置・表示用改行は、現行の`edit-plan`とROUGH_EDITの扱いへ戻す。生成済みJSONとPNGは証拠として保管し、現行の完成物には混ぜない。

## 3. 命名規則・保管場所・取り込み単位

以下は運用案であり、正式なパスとIDの扱いは`06_QUESTIONS.md`で保留する。

| 項目 | 案 |
|---|---|
| 1カットのファイル数 | 1カット=1PNG。PNG連番として扱わない。 |
| ファイル名 | `cut-<cut_id>.png`。`cut_id`は`edit-plan`と同じ安定したIDを使い、本文をファイル名へ入れない。 |
| 保管場所 | `outputs/<case-id>/telop/png/`。案件ごとに分け、別案件のPNGを混ぜない。 |
| 対応表 | `outputs/<case-id>/telop/telop-manifest.json`（案）。カットID、PNGの相対パス、開始・終了時刻、検証結果を記録する。 |
| JSONの保管 | `outputs/<case-id>/telop/json/`（案）。生成したTelop JSONと、実際にRendererへ渡した入力を分けて残す。 |

### ChatCutへの取り込み単位

現行の`02_共通_配置ゲート.md`には、次の規則がある。

> `import_audio_batch`：valid audio only、max 4 files per `import_media` session
>
> `import_video_batch`：Video-only batches、max 4

ROUGH_EDITにも、音声は「max 4 files per `import_media` session」、動画は「Video-only batches, max 4」と記載されている。つまり、音声と動画を同じ取り込み単位へ混ぜないことは確定している。

静止PNGについて、現行文書が4ファイル上限を明記している対象は音声と動画であり、PNGへの適用は未決である。運用上は、PNGも4ファイル単位のcaption-only batchとして音声・動画と分け、音声処理と動画処理の後に取り込む案とする。カット数を`N`としたとき、必要なPNGは`N`枚である。

## 5. 有効化に必要なコード側変更の一覧（コストの大きい順）

順番は、複数工程へ影響するものを上位に置いた未見積の案である。今回はどれも実装しない。

1. **Gemini台本のメタデータ出力と解析**（最大）：既存の本文を壊さず、役割・意図・感情・重要度・強調候補・映像ヒントを別フィールドとして出力・解析する。旧形式との互換性、本文だけに適用する根拠検査、途中までしか出ないメタデータの保留処理も必要になる。
2. **Telop JSON生成の呼び出し**：承認済み本文と意味メタデータを受け、Telop Generation AIを呼び出す。実行経路は未決で、JSONの生成段階と完成段階を分けて検証する必要がある。
3. **Renderer呼び出し**：検証済みのTelop JSONから、固定位置の1080×1920 RGBA静止PNGをカットごとに出力する。HTML/CSS方式かSVG方式かの選定、フォント利用条件、はみ出し停止、再現性の検査が必要になる。
4. **edit-planへのテロップ項目追加**：カットID、PNGの対応先、表示開始・終了時刻、検証済みファイルを編集計画へ結び付ける。既存の字幕本文とTelop JSONのどちらをどの項目の正本にするかは未決である。
5. **`edit_plan.py`が生成する`chatcut_steps`の変更**：現行の`caption_preset → place_captions`を、音声処理完了後の`import_telop_png_batch → place_telop_pngs`へ切り替え、`final_verify`までの順序を生成する。
6. **ChatCutへのPNG取り込み経路**：PNGをcaption-only batchとして取り込み、カットへ配置し、タイムラインを読み戻す経路を作る。テストではChrome拡張でファイル入力へ流し込む方法を使ったが、本番の経路は未確認である。ChatCutのAIプロンプト機能はこの経路に含めない。
7. **`final_verify`と受理証拠の追加**：RGBA、枚数、カットID、開始・終了時刻、透過、音声先行を一つの確認結果にまとめ、司令塔が参照できる形で保存する。
8. **配置ゲート正本の改訂**：`02_共通_配置ゲート.md`のGate C後段と`references/placement-gates.md`を、現行の`caption_preset → place_captions → final_verify`から`import_telop_png_batch → place_telop_pngs → final_verify`へ改訂し、音声先行を維持する。
9. **`timing.py`のステップ列挙変更**：`--mark-step-*`の固定値`caption_preset|place_captions`を、`import_telop_png_batch|place_telop_pngs`へ変更する。
10. **ROUGH_EDITスキルの日付フォルダ更新**：01の原文「Stage Skill folders and frontmatter names are `<logical>-YYYYMMDD`. Change both on a production-behavior change. Do not keep the previous dated folder.」を適用し、フォルダ名とfrontmatter nameを新日付へ同時更新する。

## 6. 未解決・リスク

- ヒラギノ（Macのシステムフォント）の映像利用ライセンスは未確認である。
- 語の途中改行（例：`見比/べ`）が残っている。JSONの改行禁止指定や語の辞書は仕様拡張になるため、ここでは追加しない。
- ChatCutのクレジットがテスト中に減少した原因は不明である。原因が分かるまでAIプロンプト機能は使わない。
- 推測：動きなしの静止表示は、動きを想定した要件書の想定より訴求力が下がる可能性がある。現行の手動機能で静止PNGへ動きを付けられないことを確認したため、Phase 1は静止で進める。
- Renderer方式、Telop Generation AIの実行経路、PNGの正式な保管場所、PNG取り込み上限の適用、`edit-plan`との連携項目は`06_QUESTIONS.md`で保留する。
