# Product-video core invariants

These rules apply in every stage. Product-specific values come only from the exact single `config/product_video_settings_<product_model>.v1.json` resolved for **this** case's model. Never copy another model's settings, materials, script, cuts, or Drive folder.

1. Create a separate new case and a separate new editor project. Do not change or overwrite an existing video, project, export, Drive original, or prior payload.
2. Use exactly three routine checkpoints: `台本OK`, `粗編集OK`, and `完成・書き出しOK`. Do not add upload, audio, timing, retry, or repair checkpoints. Phrases such as `編集が完了した` or `格納して` do not replace `完成・書き出しOK`.
3. The script follows `problem_or_hook -> product -> use_or_change -> result -> problem_resolution -> cta`, reads naturally between adjacent lines, and maps every claim to verified facts and visible source evidence.
4. Every user-visible caption uses a distinct source asset ID and distinct media SHA-256; the visual changes at the caption boundary. Only a no-caption tail may retain the canonical final asset.
5. Freeze exact wording, punctuation, **script** line breaks (which words belong to which cut), speaker, official preset, pitch, processing, sources, source ranges, visible action, and payload hash before `粗編集OK`. On-screen wrapping inside a cut is a layout value: it may insert display line breaks without changing characters. The settings-bounded common TTS speed and the derived live-timeline video playback speed, placement, video boundary, and caption boundary remain finish-time values: adjust them without a new checkpoint when the frozen source asset/range, action, text, and voice identity stay unchanged.
6. Every narration-target caption has exactly one matching TTS clip. Use one speaker, official preset, common speed, pitch, and processing throughout. When official Holiday Twist audio is generated in bulk, insert measured silent scene-split gaps and cut only at those gaps so the timeline still has one TTS clip per narration-target caption; do not leave one combined clip. For every non-final cut, align the source clip, caption clip, and TTS clip to the same start frame and the same end frame; that shared end is also the next cut's shared three-layer start. Remove task-owned TTS trailing silence first and keep the actual audible speech end within zero to one frame of the shared end. Never pass a repair that moved only one or two of the three layers. Only the configured canonical final cut may keep a full-length visual-and-caption tail after narration; when needed, split the canonical source at the TTS end and treat the preserved remainder as the tail segment without shortening it. For every cut, also prove the expected source clip exists, source audio is exact-muted rather than merely attenuated, exactly one caption layer renders, and the source is non-black at the first valid frame, representative midpoint, and last valid frame. Verify uninterrupted full playback, every boundary during playback, and the same saved project after reload; timeline numbers alone never prove completion.
7. Every final caption rendering must be centered, non-duplicated, fully inside the visible safe area, and prominent (heavy weight, thick dark stroke, contrast band). Visual wrapping may insert display line breaks at existing punctuation or phrase boundaries without changing frozen characters; spoken TTS text stays the frozen line. When product settings name an official CapCut template, read back that actual resource; a different host editor must not claim that CapCut read-back.
8. Never infer a production ordinal, Drive destination, collision result, task-owned tab, account choice, or unknown export/upload outcome. Use the most specific HOLD. The standing Drive parent is exactly one folder titled with the verified product model.
9. The three checkpoints do not authorize posting, publishing, external send beyond the approved Drive 格納 of this case's new export, credit purchase, third TTS attempt, unknown-result retry, overwrite, or deletion of originals, Drive objects, receipts, or another case. Exact `完成・書き出しOK` bound to the current final-QA receipt authorizes one new export and, unless the original request explicitly required `export_only`, one new Drive file.
10. Credentials, cookies, tokens, account IDs, session URLs, raw Drive IDs, and task tab IDs do not enter portable payloads or ordinary logs.
11. After `COMPLETE` and verified destination storage, purge this case's local working media on every machine that held a copy. Do not add a fourth checkpoint. Never delete the sole remaining completed video, originals, Drive stored objects, git-tracked files, receipts, or shared working copies still required by an in-progress case.

CapCut logout recovery uses only the official CapCut TikTok login plus the existing Chrome TikTok session or saved-credential autofill. CAPTCHA, 2FA, recovery, new consent, or ambiguous account choice is `HOLD_CAPCUT_LOGIN_USER_ACTION_REQUIRED`.
