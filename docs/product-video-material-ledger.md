# 商品動画スキル：素材台帳

型番ごとの素材の中身をオブシディアンに置き、この Mac の AI がそれを読んで台本と素材選定に使う。20260923 の stage skill がこの動作です。実行の正本は `.cursor/skills/product-video/SKILL.md` と、そこから開く日付付き stage skill です。

## 結論

人が編集する正本は、オブシディアンのローカルフォルダ（ヴォルト）です。登録者本人の1アカウントを、複数の Mac で開きます。Obsidian Sync で同じヴォルトを同期します。パスワードは本人以外に渡しません。

制作 Mac の台本作成と素材選定は、同期済みのノートを読んで、既存の visual catalog に反映してから動きます。動画ファイルと、完成動画の Drive 格納フォルダは、今まで通りそれぞれの場所にあります。ノートがその索引です。

## 場所

| もの | 場所 |
| --- | --- |
| 人が編集するノート | オブシディアンのヴォルト。Git には置かない |
| この Mac 上のパス | 機械ごとのローカル設定。Sync のリモートヴォルトは1つで、フォルダの絶対パスは Mac ごとに違ってよい |
| AI が選定で読む台帳 | `.runtime/product-video-visual-catalog/<MODEL>.v1.json` |
| 動画ファイル | `PRODUCT_VIDEO_MATERIAL_ROOT`、未設定なら `.runtime/product-video-inputs/<MODEL>`。既存の `<MODEL>_コピー` だけがある型番は、そのフォルダのまま |
| 完成動画 | 型番名の Drive フォルダ。ノートには置かない |

ヴォルトが無い、またはこの Mac で Obsidian が起動していないときは、台本作成と素材選定に入らず止めます。同期完了を返す公式の合図は無いので、起動していることと、ヴォルトのフォルダが読めることを条件にします。起動直後でノートがまだ落ちていなければ、一度だけ同期を待ってから読みます。

## ノートの形

型番フォルダの中に、素材の相対パスと同じ位置で、動画1本につき1ノートを置きます。

```text
AN-S182/コンパクト収納/IMG_0373.md
```

1ノートの中に複数の場面を書きます。画面の物、動作、商品の状態、場所、画角が変わったところが場面の区切りです。フォルダ名だけを場面の説明にはしません。

各場面の項目は、選定がすでに照合している項目と同じです。

- 開始秒、終了秒
- 画面に映っていることの一文
- 物、動作、商品の状態、場所、画角、見た目の特徴

セリフとの対応、画質の点数、ファイル名を場面の説明の代わりには書きません。効く語は、その画面に映っている具体的な物と動作です。

ノートには、元動画のサイズと更新時刻を持たせます。これが、見直すかどうかの判定です。

## 誰が書くか

ノートが正本です。書く経路は2つです。

1. Gemini 3.8 Flash が、表に無い動画と、ファイル自体が新しくなった動画を見て、場面の項目をノートに書く。
2. 人がオブシディアンで直す。直した文を、その後の台本と選定が読む。

ファイルが変わっていないノートは、案件のたびに映像を見ません。AN-S182 のように、既存の visual catalog に使える場面文があるファイルは、その文をノートの初期内容にします。場面文が無いファイルだけ、Gemini が見ます。

動画ファイルのサイズか更新時刻が変わったときは、新しいバイト列を見てノートの場面を書き直します。前のファイルに対する修正は、新しいファイルには引き継ぎません。戻すときは Obsidian Sync の履歴を使います。

## 映像の見方

台本と同じく、この Mac の Antigravity CLI（`agy --print`）で、モデルは `gemini-3.8-flash`、effort は medium です。API キー、Gemini.app、Cursor のモデル切替、別の Flash や Pro には落としません。ログイン、枠切れ、別モデル、ファイルを書き始めた場合は、台本と同じ HOLD で止めます。

台本の送信は、これまで通り文章だけを渡し、ファイルを読ませません。映像を見る送信は、それとは別の一回送信です。こちらは画面を見るので、台本の「ファイルを読むな」という指示は付けません。

手順は次のとおりです。

1. 既知の時刻で静止画を切る。秒数は、この切り出しが持っている。
2. 静止画フォルダを `agy` に渡し、各時刻に映っている物、動作、商品の状態、場所、画角を書かせる。秒数は作らせない。
3. 説明が同じで続く区間を1場面にする。境界は、静止画の時刻である。
4. その項目を、該当動画のノートに書く。

`agy --print` には画像添付の専用フラグがありません。最初の1本で、返った説明とその静止画を突き合わせ、画像を読んだと確認できないときは、そこで止めます。別の読み方には切り替えません。確認できたあと、残りの未記入ファイルを同じ送り方で続けます。

## 台本

台本作成の直前に、ノートが catalog より新しければ catalog へ反映します。

Gemini に渡すのは、場面の説明だけです。物、動作、商品の状態、場所、画角です。ファイル名、開始秒、終了秒は渡しません。同じ説明は1つにまとめ、ノートの全文は渡しません。

台本は、その一覧にある画面を優先してシチュエーションを書きます。一覧のどれもセリフに合わないときだけ、新しいシチュエーションを書いてよいです。商品の性能や数値は、商品情報からだけ使います。台本にファイル名と秒数は書かせません。

## 素材選定

素材選定の直前にも、同じ反映をします。どのファイルの何秒を使うかは、ノート由来の catalog を読んで決めます。尺、履歴、catalog の項目一致、見た目の差、source の分散は、これまで通りこの Mac のコードが決めます。JEV はファイルを開かず、秒数の比較もせず、台本も書きません。

意味がコードで1つに決まらなかったカットだけ、JEV の `jev_rank` を使います。呼び出しはカットごとに1回です。渡すのは、そのカットの凍結したセリフとシチュエーション、および尺を満たす場面の説明です。場面の id と、物、動作、商品の状態、場所、画角、画面の一文だけを候補にします。ファイルの中身、パスワード、トークンは渡しません。候補が1つならその場面を使い、JEV は呼びません。候補が0なら、そのカットで止めます。

`jev_rank` の先頭が、そのセリフに実際に合うと返したときだけ採用します。順位を付けただけで合うと言っていない結果、`review`、`escalate`、coverage が足りない結果は採用せず、そのカットで止めます。近いというだけの別の場面では埋めません。凍結したセリフは書き換えません。人がノートを足すか、台本の段階に戻して人が直します。

この意味判断に Gemini は使いません。Gemini 3.8 Flash が行うのは、未記入またはファイルが新しくなった動画を見ることと、台本の文を書くことです。

## 案件の中での位置

通常の入力は、いままで通り `/product-video`、exact `案Nで台本OK`、exact `完成・格納してください` です。

```text
ノートを読む
  → 未記入またはファイルが新しい動画だけ Gemini が見る
  → 人がノートを直す
  → 台本（一覧にある画面を優先）
  → 案Nで台本OK
  → 選定（同じノート。意味が複数残ったカットだけ JEV が順位を決める）
  → 合わないカットは停止
  → 以降は現行のナレーション、粗編集、格納
```

反映は台本作成の直前と、素材選定の直前です。人が「反映して」と言う必要はありません。

## この設計が変えないもの

- 動画ファイルの保管場所と、Drive への完成動画の格納
- 商品事実に無い性能や数値を台本に足さないこと
- 凍結後のセリフ、ナレーション、テロップを同じ文のままにすること
- 案件のたびに全動画を見直さないこと
- ナレーション、粗編集、書き出し、格納の手順
